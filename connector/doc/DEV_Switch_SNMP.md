# DEV Switch SNMP

## About

The **DEV Switch SNMP** connector monitors and controls devices that support the dev-switch MIB, using SNMP. It was originally designed for the DEV7113 1:1 (without applied redundancy functionality) and was later extended to a generic version. Depending on the version range, the connector can create a DVE element for every module found in the **Port** table.

## Key Features

- **Device overview**: Displays general device information and allows the control and switch mode to be configured.
- **Switch configuration**: Shows the switch groups and switch units, and allows the switching status of a switch unit to be checked or changed.
- **Port monitoring**: Displays the raw information of every port in the device, including the slot location of each port.
- **Module DVEs**: Creates DVE elements for the modules found in the port table, which are processed by the exported connector **DEV Switch Module**.
- **Alarm and surveillance information**: Enables and disables the different alarm trap types, lists the alarms generated by the device, and shows the device and fan status.

## Use Cases

### Monitoring Switch Ports

**Challenge**: Operators need a clear overview of the state of every port of a switch, but the raw information is spread over many MIB columns.

**Solution**: The connector exposes the contents of the dev-switch MIB port table in DataMiner, with a dedicated page for the port data and the slot location of each port.

**Benefit**: Operators can check port information from a single place and use DataMiner alarming on the monitored values.

### Per-Module Visibility with DVEs

**Challenge**: In devices where two ports together form a module, operators want to follow up on each module separately.

**Solution**: Based on the port table, the connector can create a DVE element for each module. DVEs can be hidden or shown in the Surveyor, and are not deleted automatically when a module disappears from the device.

**Benefit**: Each module can be followed up on its own, and trending data is preserved when a module is removed from the device and installed again.

### Controlling Switching and Alarm Traps

**Challenge**: Operators want to check or change switching status and decide which alarm traps the device sends, without logging in to the device itself.

**Solution**: The connector provides the switch group and switch unit tables, and the alarm configuration with toggles for the different alarm trap types. A link to the web interface of the manufacturer is available as well.

**Benefit**: Day-to-day switching and alarm configuration can be handled from DataMiner, while the manufacturer web interface remains one click away.

## Technical Reference

### Prerequisites

- **SNMP access** to the device is needed, with a get community string to read from the device and a set community string to change settings.
- **Remote mode** on the device is needed to change settings via SNMP through DataMiner.
- **Network access** from the client machine to the device is needed to open the web interface of the manufacturer.

### Notes on DVEs

- DVEs are not deleted automatically when a port disappears, so that trending data is kept if the module is reinstalled. Modules marked as removed can be deleted manually.
- DVEs can be hidden or shown in the Surveyor without being deleted.
- Two-port modules are only supported from range 3.0.0.x onward and are only accurate for the DEV7113 1:1.
